# Rule: 技术方案 ≥3 对比（solution-options-comparison）

**适用范围**：需求确定后、进入技术方案讨论时——`/opsx:explore` 的方案对比环节、设计讨论、以及 OpenSpec `design.md` 的 Decisions 撰写。**不适用**于需求澄清阶段本身（先确认需求，再谈方案）。

## 做什么（MUST）

1. **至少提出 3 种可行技术方案**（含常见默认方案）。少于 3 种不算「对比」，直接选型需用户明确豁免。
2. 每个方案给出：**优点 / 缺点 / 适用场景 / 主要成本或风险**。
3. 用**对比表**并排差异点（性能、成本、复杂度、维护、生态、与本仓库既有模式的契合度等维度的关键项）。
4. **给出推荐**，写明推荐理由，并说明被否方案各自的一句话原因（为什么不是 X）。

## 不做什么（MUST NOT）

- 不得在只有 1-2 个方案时直接下结论或进入实现。
- 不得跳过优缺点 / 适用场景分析就直接做选择。
- 不得以「最简单 / 最常规」代替分析作为推荐理由。
- 不得在需求未澄清时就盲目展开方案细节比拼。

## 为何（WHY)

单方案讨论暴露不了 trade-off，选择容易在实现中途被推翻、返工。≥3 方案强制摊开约束与取舍，让推荐基于证据而非默认偏好，与本仓库 ADR「每决策含备选方案与否决理由」的既有约定（见 `docs/adr/` 模板）保持起点一致。
